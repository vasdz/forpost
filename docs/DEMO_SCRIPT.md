# Сценарий демонстрации — 5 минут

Сценарий показывает фактическое состояние платформы. Он не использует
синтетические записи, не открывает `data/` в терминале и не демонстрирует
прогнозы, пока ML-контракт и валидированный артефакт не переданы.

## Подготовка ведущего

1. На машине владельца данных вручную создать локальный снимок по
   `docs/LOCAL_VERIFY.md`.
2. Убедиться, что `git ls-files -- data` выводит только допустимую документацию
   либо не выводит ничего до первого коммита `data/README.md`.
3. Запустить `npm run dev` и открыть только `http://127.0.0.1:3000`.
4. Не выводить в консоль JSON-снимок, первичные файлы, имена исходных файлов
   или идентификаторы полученных выгрузок.

## 0:00–0:40 — проблема и границы

Скажите: «ФОРПОСТ помогает диспетчеру видеть подтверждённую оперативную
обстановку и готов принимать прогнозы ML-команды. Система не заменяет
диспетчера и не управляет оборудованием». Покажите раздел «Обзор» и отметку
«Локальный обезличенный снимок».

## 0:40–1:30 — реальные данные без имитации

Откройте «Реестры» и «Журналы наблюдений». Покажите фильтрацию, таблицу и
timeline playback. Если источник отсутствует, покажите понятное состояние
«Данные недоступны», а не пустую таблицу и не сгенерированные KPI.

Скажите: «UI читает только ограниченный локальный снимок через
`GET /api/local-situation`; компоненты не импортируют исходные файлы и не
вычисляют риск».

## 1:30–2:15 — доступность и UX

Переключите тёмную и светлую темы, покажите сохранение темы после обновления
страницы. Перемещайтесь по timeline с клавиатуры, затем покажите доступную
табличную альтернативу графика. Отметьте, что прогнозные разделы до подключения
ML показывают состояние недоступности вместо подмены фактов прогнозами.

## 2:15–3:05 — защита данных

Покажите в редакторе [data/README.md](../data/README.md),
[scripts/pre-commit-guard.mjs](../scripts/pre-commit-guard.mjs) и
[docs/LOCAL_VERIFY.md](LOCAL_VERIFY.md). Объясните четыре барьера: root-only
`.gitignore`, local hooks, CI-gate и обязательный server-side pre-receive.

Скажите: «Защиту до принятия push обеспечивает только pre-receive/DLP на
Git-хостинге; его установку подтверждает администратор. CI не считается
заменой этой меры».

## 3:05–3:45 — fail-closed API

Покажите код `apps/api/src/forpost_api/dependencies.py` и тест
`tests/security/test_api_hardening.py`. Объясните: отсутствие или неверная
Bearer-схема даёт `401`, поддельные `x-role`/`x-user-id` не создают личность,
а Bearer без доверенного LDAP/AD-провайдера получает `503`.

## 3:45–4:30 — качество и воспроизводимость

Покажите команды из раздела «Проверки» в README и CI workflow. Назовите
гейты: lint, typecheck, unit/integration tests, build, Ruff, Bandit, Semgrep,
TruffleHog и dependency audit. Покажите только итоговые статусы команд, не
пути и содержимое локальных данных.

## 4:30–5:00 — hand-off ML и следующий шаг

Скажите: «Следующее интеграционное условие — версия
`docs/API_CONTRACT.md` и реальный экспорт ML. Тогда платформа добавит
`/api/predictions`, probability, horizon, factors и поток: прогноз → решение
диспетчера с причиной → аудит. ML-логику платформа не копирует и не
пересчитывает».

Не показывайте `ml/`, `models/`, notebooks, исходные датасеты и обучающие
скрипты: это независимая зона ML-команды.
