# Проект повышения технической готовности к экспертизе

## Цель

Максимально увеличить проверяемую оценку решения по техническим критериям ТЗ,
не имитируя отсутствующие корпоративные источники и не ослабляя quality gates.

## Границы

В работу входят код, автоматические проверки и техническая документация. Не
входят презентация, публичный хостинг и материалы питч-сессии. Первичные данные
остаются только в `data/`; отчёты не раскрывают строки, идентификаторы, имена
файлов или характеристики закрытой выгрузки.

## Решение

### Единый локальный запуск

Команда `npm run dev:stack` запускает FastAPI и Next.js на loopback, передавая
обоим процессам один случайный service token. Она не принимает произвольные
адреса или аргументы, устанавливает локальный `PYTHONPATH`, корректно завершает
оба дочерних процесса и не печатает секрет. Это устраняет ситуацию, когда UI
работает, а топология и backend-маршруты возвращают `503` только из-за
неподнятого API.

### Доказательность ML

Каждая попытка обучения формирует локальный минимизированный отчёт оценки в
`data/processed/ml-evaluation.json`. Отчёт не является модельным релизом. Он
содержит задачу, статус `published` или `rejected`, причину отказа из
фиксированного безопасного словаря, пороги, доступные validation/test-метрики,
размеры временных частей и момент оценки. Если validation gate не пройден,
финальный test остаётся нетронутым и в отчёте отсутствует.

Backend отдаёт отчёт read-only по строгой схеме. Next.js BFF и интерфейс
показывают карточку качества: статус, горизонт, temporal split, пороги и
метрики, а также явно отделяют validation от финального test. Наличие отчёта
не разрешает публикацию прогнозов: `/api/predictions` по-прежнему требует
валидный атомарный release.

### Проверяемая производительность

Локальный smoke/load runner создаёт 20 конкурентных read-only пользователей
через ASGI transport, проверяет `/api/availability` и `/api/v1/topology`,
считает число ошибок и p95. Он использует временный обезличенный снимок и не
читает `data/raw`. Машиночитаемый итог позволяет воспроизводимо подтвердить
минимум из ТЗ, не выдавая локальную проверку за production SLA.

### Документация

Матрица соответствия, инструкция запуска, ML-методика и README синхронизируются
с фактическим кодом. Реализованное помечается реализованным только при наличии
теста; ограничения production-контура остаются явными.

## Ошибки и безопасность

- Отсутствующий или некорректный ML-отчёт даёт `503`, а не пустые метрики.
- Поля отчёта имеют allowlist, численные границы и ограниченный размер файла.
- Текст исключения не сериализуется напрямую: наружу попадает только безопасный
  код причины.
- Все процессы слушают только `127.0.0.1`.
- Локальный load test не меняет данные и не проверяет write-маршруты.

## Проверка

Изменения выполняются test-first. Завершение требует целевых unit/integration
тестов, полного Vitest/pytest, ESLint, TypeScript strict, Ruff, Bandit,
production build и воспроизводимого запуска load runner.
