# Периметр локальных данных

## Правило хранения

Первичные и производные данные организатора хранятся исключительно в локальном
игнорируемом каталоге `data/`. В репозиторий, логи, тестовые фикстуры,
документацию, CI-артефакты и внешние сервисы не передаются ни записи, ни
производные сводки, ни идентификаторы, ни хэши, ни размеры, ни временные
границы конкретной выгрузки.

В Git намеренно нет исключений внутри `data/`. Проверка периметра блокирует
добавление корневых путей `data/**` в индекс и историю, включая варианты
регистра, а CI повторяет проверку всех добавленных коммитов. Локальный pre-push
guard выполняет ту же проверку до сетевой отправки после установки хуков.

## Разрешённый локальный контур

Адаптер снимка работает только с предварительно согласованными локальными
CSV-ролями:

| Роль | Назначение в приложении | Обращение UI |
| --- | --- | --- |
| Журнал наблюдений | Факты наблюдаемых событий | Только через минимизированный локальный API-снимок |
| Справочник каналов | Атрибуты каналов датчиков | Только через минимизированный локальный API-снимок |
| Иерархия объектов | Негеографические связи объектов | Только через минимизированный локальный API-снимок |

Загрузчик принимает только строгие документированные схемы, ограничивает объём
производного снимка и не записывает диагностические значения строк. В JSON-
снимок и браузер не передаются агрегаты подготовки снимка. Клиент не
читает файлы из `data/`: он использует только относительный маршрут локального
Next.js-приложения. Маршрут должен работать исключительно на loopback-интерфейсе
и не должен публиковаться через reverse proxy или LAN.

## Что отсутствует в текущем контуре

Без отдельного подтверждённого источника не выводятся и не имитируются данные
о допусках, доступе, ремонтах, оборудовании, погоде, координатах, заявках и
ML-прогнозах. Такие возможности интерфейса должны показывать только явное
состояние недоступности, а не нулевые или синтетические значения.
