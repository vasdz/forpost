# Формализация ML-задач

Этот документ фиксирует целевые правила до обучения. Фактический баланс классов,
число позитивных примеров, временные границы и метрики создаются только в
игнорируемом локальном контуре после запуска и не публикуются здесь.

## Единые правила

- Горизонты: 24, 48 и 168 часов.
- Окно разметки сдвигается только по времени; признаки строятся из событий строго
  раньше точки прогнозирования.
- Обучение возможно только при подтверждённых источниках и достаточном числе
  позитивных примеров. При недостатке используется только маркировка
  `training_unavailable`, без искусственных метрик.
- Разделение train/validation/test всегда хронологическое; последние наблюдения
  резервируются для holdout.

## Отказ датчика

| Поле | Правило |
| --- | --- |
| Target | Вероятность отказа канала в заданном горизонте. |
| Доступный прокси-лейбл | Отсутствие последующих наблюдений канала дольше согласованного порога тишины. |
| Приоритетный лейбл | Подтверждённая запись ремонта, замены или неисправности после подключения истории обслуживания. |
| Признаки | Частоты и статистики значений по окнам, интервалы между событиями, тренд, календарные признаки, тип канала. |
| Ограничение | Прокси тишины не равен подтверждённой поломке и не должен называться отказом в UI. |

## Пожарный риск и подтопление

| Поле | Правило |
| --- | --- |
| Target | Вероятность подтверждённого дымового, температурного или пожарного инцидента в горизонте. |
| Лейбл | Верифицированное событие smoke/temperature, не отмеченное ложным, после подключения результата проверки. |
| Дополнительные признаки | Разрешённые горячие работы по секции, события pump, метеоданные — только после подключения локальных источников. |
| Ограничение | Состояние тревоги само по себе не является подтверждением пожара или ложного срабатывания. |

## Несанкционированный доступ

| Поле | Правило |
| --- | --- |
| Target | Вероятность подтверждённой аномалии доступа в горизонте. |
| Лейбл | Событие contact/movement вне подтверждённого окна допусков с верификацией результата. |
| Подход | Аномальный score плюс классификатор только после появления размеченных инцидентов. |
| Ограничение | Без журналов СКУД, допусков и результата проверки задача недоступна для обучения. |

## Износ инфраструктуры

| Поле | Правило |
| --- | --- |
| Target | Вероятность ремонта в окне либо время до ремонта. |
| Лейбл | Подтверждённая запись ТО, ремонта или замены. |
| Признаки | Возраст, история ремонтов, интенсивность, инспекции, сезонность и доступные внешние факторы. |
| Ограничение | Без истории обслуживания не строится ни survival-модель, ни классификатор ремонта. |

## Матрица доступности

`forpost_prediction_core.capabilities.assess_task_capability` является единственной
точкой принятия решения о запуске обучения. При недостающем источнике она возвращает
перечень классов данных, а не заменяет их синтетическим лейблом или прогнозом.
