# Аудит ML-части

Документ фиксирует проверяемую реализацию, но не публикует факты конкретной
локальной выгрузки. Численные метрики принадлежат локальному неизменяемому
model card и появляются только после прохождения всех quality gates.

| Артефакт | Состояние | Защитное свойство |
| --- | --- | --- |
| Загрузчик обучающего окна | реализован | Читает ограниченный непрерывный правый хвост локальных CSV, проверяет схему/год и не сериализует dataset. |
| Point-in-time dataset | реализован для `sensor_failure` | Каждый признак использует только события до cutoff, proxy-лейбл — отдельное будущее окно 24 часа. |
| Временная проверка | реализована | Fit, calibration, validation и test упорядочены по времени и разделены 24-часовым embargo; границы адаптируются к неравномерным временным точкам без уменьшения embargo. |
| Кандидаты | реализованы | Logistic Regression, Extra Trees и HistGradientBoosting сравниваются с dummy baseline; sigmoid и isotonic-калибровки конкурируют только на validation. |
| Quality gate | реализован | Precision/recall ТЗ, PR-AUC относительно baseline, F1, alert rate, ECE, Brier score и batch latency проверяются до публикации; test не участвует в выборе. |
| Registry | реализован | Новый `vN` публикуется атомарно; Skops-типы, схема model card и SHA-256 manifests проверяются до serving. |
| Prediction API/UI | реализован | Только согласованный локальный export попадает в FastAPI и UI; отсутствие/повреждение релиза даёт `503 pending`. |
| Решение диспетчера | реализовано локально | Human-only endpoint связывает решение с существующим текущим прогнозом и пишет его в hash-chain audit ledger. |

## Доказательность четырёх задач

- `sensor_failure`: доступна только proxy-задача прекращения телеметрии. Она не
  равна подтверждённой физической поломке датчика.
- `fire_risk`: нет верифицированных исходов пожара и полного контекста горячих
  работ — вероятностный релиз блокируется.
- `unauthorized_access`: нет согласованных СКУД, допусков и результатов
  расследований — вероятностный релиз блокируется.
- `infrastructure_wear`: нет истории ТО/ремонтов/замен с устойчивым ID объекта —
  вероятностный релиз блокируется.

Наличие экранов для четырёх направлений не означает наличие четырёх моделей.
Интерфейс показывает фактическую доступность и evidence tier, а не создаёт
демонстрационные вероятности.

## Вывод

Репозиторий содержит воспроизводимый локальный ML-контур для единственной
задачи, которую позволяют текущие источники. Его сильная сторона — отказ от
публикации при недостаточной доказательности. Переход от `proxy` к `validated`
возможен только после независимых записей проверки, ремонта или замены и новой
версии стратегии разметки.
