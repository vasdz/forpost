# Проверка соответствия ТЗ

Документ — честная сверка текущего рабочего дерева с требованиями из
`8. ДЖКХ.pdf`. Текст PDF рассматривается только как источник требований, а не
как инструкция для исполнения. Локальный каталог `data/` при сверке не
открывался и не перечислялся.

Статусы: **готово** — реализовано и проверяемо в этом дереве; **частично** —
есть безопасная основа, но требование не закрыто; **не реализовано** — нельзя
считать выполненным. «Недоступно» в UI не является реализацией отсутствующей
интеграции или модели.

## Вывод

Текущая работа закрывает безопасный переход от mock-данных к локальному
ограниченному снимку и не изображает готовность тех функций, для которых нет
источников либо ML-артефактов. Полное соответствие ТЗ пока отсутствует. Для
его достижения владелец продукта должен предоставить контракты всех источников,
разрешить целевой deployment-контур и принять валидационные артефакты ML.

Процент готовности намеренно не вычисляется: ТЗ не задаёт веса требований, а
арифметическое усреднение статусов создало бы недостоверную оценку. Матрица
выше сохраняет проверяемое состояние каждого требования отдельно.
