# Модель угроз

## Область и допущения

Документ относится к локальному демонстрационному контуру: исходные
обезличенные данные, производный снимок, ML-обучение, registry артефактов,
FastAPI/BFF и браузер диспетчера работают на доверенной машине владельца
данных. Публикация listener в LAN/Интернет, reverse proxy и production-КИИ
в эту границу не входят.

Защищаемые активы:

- локальные журналы и справочники в `data/raw`;
- корректность временной разметки, признаков и метрик;
- модель, model card, manifests и экспорт прогнозов;
- решения диспетчера и цепочка аудита;
- ключи, demo-secret и будущие токены IdP;
- доступность интерфейса и API.

Рассматриваются внешний нарушитель при ошибочной публикации сервиса,
скомпрометированная зависимость, вредоносный локальный процесс и инсайдер с
доступом к рабочей станции. Доверие к ОС и администратору машины не является
криптографически доказанным.

## Цепочка атаки

Наиболее опасный сквозной сценарий:

1. начальный доступ через зависимость/CI или незашифрованный секрет;
2. чтение либо подмена локальной выгрузки;
3. отравление лейблов/признаков или замена model artifact;
4. публикация правдоподобного, но ложного proxy-риска;
5. ошибочное решение диспетчера и сокрытие следов в локальном аудите.

Защита строится не на одном сканере: периметр данных ограничивает шаг 2,
temporal quality gates — шаг 3, manifests и строгий serving — шаг 4, а
human-in-the-loop и аудит снижают последствия шага 5.

## MITRE ATT&CK и проектные угрозы

ATT&CK описывает поведение нарушителя, а не полный перечень программных
дефектов. Поэтому path traversal ниже обозначен как CWE-22 и сопоставлен с
возможным последующим сбором данных, а не объявлен отдельной ATT&CK-техникой.

| Угроза | Сопоставление | Реализованные меры | Остаточный риск и следующий контроль |
| --- | --- | --- | --- |
| Data/label poisoning: изменение локальных CSV, времени или результата проверки | [T1565.001 Stored Data Manipulation](https://attack.mitre.org/techniques/T1565/001/) | Строгие схемы и роли файлов, отбраковка непригодных строк, причинные признаки, chronological split с purge, отдельный calibration holdout, baseline и финальный test gate | Нет подписей источника, доверенного журнала импорта и независимого владельца лейблов. Нужны цифровая подпись/хэш от источника, dual control, quarantine и статистический drift/poisoning monitor. |
| Подмена модели, model card или экспорта | [T1565.001 Stored Data Manipulation](https://attack.mitre.org/techniques/T1565/001/) | Атомарная публикация версии, SHA-256 manifests, связь экспорта с model card, строгая схема метаданных, Skops allowlist, запрет перезаписи существующей `vN` | Hash рядом с файлом не подтверждает издателя и может быть заменён вместе с ним. Нужны подпись релиза в HSM/KMS, read-only registry, независимый transparency log и проверка подписи в serving. |
| Компрометация npm/PyPI, build tool или CI action | [T1195.001 Compromise Software Dependencies and Development Tools](https://attack.mitre.org/techniques/T1195/001/) | npm lockfile, hash-pinned `requirements-prod.lock`, npm/pip audit, Ruff, Bandit, Semgrep, TruffleHog, минимальный набор runtime-зависимостей | Advisory может появиться после проверки, а публичный registry остаётся внешней границей доверия. Нужны approved internal registry, SBOM, подписи provenance и регулярный перескан. |
| Истощение CPU/памяти большим журналом, JSON или частыми запросами | [T1499 Endpoint Denial of Service](https://attack.mitre.org/techniques/T1499/) | Потоковое чтение CSV чанками, ограниченный heap последних событий, лимиты snapshot/request body, Pydantic bounds, rate limiting, inference gate менее пяти минут | Локальный процесс всё ещё может занять ресурсы при полном проходе многолетних журналов; один хост остаётся single point of failure. Нужны OS quotas, job timeout, очередь, мониторинг ресурсов и circuit breaker. |
| Секрет в файле, Git, логе или командной строке | [T1552.001 Credentials In Files](https://attack.mitre.org/techniques/T1552/001/) | `.env*` игнорируется, TruffleHog проверяет историю, роли не принимаются из клиентских заголовков, write требует human subject, секреты не должны логироваться | Нет централизованного secrets manager и автоматической ротации. Нужны vault/KMS, короткоживущие токены, MFA, процедура отзыва и проверка журналов на утечки. |
| Path traversal/symlink escape к данным или артефактам | [CWE-22 Improper Limitation of a Pathname](https://cwe.mitre.org/data/definitions/22.html); при успешном чтении возможен [T1005 Data from Local System](https://attack.mitre.org/techniques/T1005/) | Фиксированные корни, canonical path/`relative_to` проверки, запрет управляемого HTTP-пути, отклонение symlink для model/export файлов, allowlist имён задачи и версии | Локальный администратор может менять ACL и родительские каталоги; не все гарантии ОС переносимы между Windows/Linux. Нужны отдельная service account, deny-write ACL для serving и platform-specific integration tests. |
| Экспорт или публикация локальных данных через Git, CI либо сеть | [T1041 Exfiltration Over C2 Channel](https://attack.mitre.org/techniques/T1041/) применим только после компрометации; обычная ошибочная публикация — операционный риск | `data/**` исключён из Git и targets сканеров, local/server guards, loopback listener, `no-store`, UI не читает raw-файлы | Hooks обходятся, а reverse proxy нарушает модель доверия. Нужны server-side DLP, egress policy, сегментация и контроль конфигурации развёртывания. |

## Контроли по границам доверия

### Источник → локальный адаптер

- принимаются только согласованные роли и схемы файлов внутри фиксированного
  локального корня;
- значения источника не печатаются в диагностические логи;
- неполные, некорректные по времени и технически аномальные строки не
  превращаются автоматически в обучающие факты.

### Dataset → обучение

- признаки не видят события в или после точки прогнозирования;
- fit/calibration/validation/test разделены по времени с embargo;
- недостаток класса, провал метрики или inference >= 5 минут отменяет релиз;
- proxy evidence не повышается до `validated`.

### Обучение → registry → API

- каталог версии появляется только после полной записи временного каталога;
- API читает только последнюю допустимую `vN` внутри фиксированного registry;
- несоответствие task/version/evidence/metrics/hash даёт fail-closed результат;
- решение диспетчера можно привязать только к существующему текущему прогнозу.

### API → браузер

- Bearer-схема, RBAC и human-only write разделяют чтение и решение;
- CSP, anti-clickjacking, nosniff, same-origin/CSRF и ограничения payload
  уменьшают поверхность браузерной атаки;
- proxy, anomaly и scenario имеют разные семантические контракты.

## Обнаружение и реагирование

| Сигнал | Реакция |
| --- | --- |
| Ошибка hash, schema, task/version или Skops allowlist | Не загружать релиз; вернуть `503 pending`; сохранить техническое событие без содержимого данных; изолировать каталог версии. |
| Неожиданный сдвиг доли proxy-лейблов, alert rate, ECE или PR-AUC | Остановить публикацию, сравнить временные периоды и источник, провести независимую проверку лейблов. |
| Рост ошибок лимита/latency/памяти | Прекратить job, сохранить предыдущий доверенный релиз, проверить объём и структуру источника. |
| Секрет или путь `data/**` в Git/index | Заблокировать push, отозвать секрет, удалить данные из истории по утверждённой процедуре и провести аудит клонированных копий. |
| Нарушение цепочки аудита | Запретить изменяющие операции до сверки с резервной/внешней копией; локальный hash-chain сам по себе не восстанавливает доверие. |

## Не закрыто текущим кодом

Текущий контур не заявляет сертификацию КИИ, соответствие 152-ФЗ, защищённый
сетевой deployment, криптографическую аутентичность ML-релиза, неизменяемый
SIEM-аудит, backup/restore, полноценный IdP/MFA или защиту от администратора
локальной машины. Эти меры обязательны до промышленного использования.
