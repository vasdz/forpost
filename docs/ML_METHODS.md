# Методы и ограничения локального ML-контура

## Воспроизводимость

Все операции выполняются локально. `ml/config.yaml` фиксирует seed, горизонты,
окна признаков, минимальный размер позитивного класса и пороги. Feature schema
version сохраняется вместе с будущим model card; модель с несовместимой схемой
не может обслуживать прогноз.

## Feature store

`forpost_prediction_core.features.build_channel_features` строит показатели
канала для точки `cutoff` только из записей с временем строго раньше `cutoff`.
В единый контракт входят частоты и статистики значений на окнах, время с
последнего события, энтропия межсобытийных интервалов, тренд значения, календарь
точки прогнозирования и подтверждённые атрибуты канала.

`forpost_prediction_core.splits.split_by_time` сортирует наблюдения по времени
и создаёт непересекающиеся train, validation и test. Случайное перемешивание не
допускается.

## Лейблы и модели

Для отказа датчика допускается только слабый локальный прокси «тишина в
горизонте», отдельно от подтверждённой неисправности. Его нельзя представлять
как фактический отказ или использовать для автоматического решения.

Остальные задачи требуют недоступных в текущем контракте источников: результатов
верификации, СКУД и допусков, истории ремонта и, где применимо, работ и погодных
данных. `assess_task_capability` блокирует обучение до их появления.

После появления подтверждённых лейблов обязательны: сравнение с наивным и
правиловым baseline, калибровка вероятности, временной holdout, precision,
recall, F1, PR-AUC и ROC-AUC. Функция `evaluate_binary_probabilities` не
публикует метрики, если в holdout отсутствует любой класс.

## Объяснимость и serving

Набор вкладов модели сначала проходит проверку конечности, сортируется по
абсолютному влиянию и нормируется к сумме единица. До появления верифицированной
модели это не заменяет TreeSHAP и не формирует прогнозы.

API остаётся в явном статусе недоступности, пока не будет локально проверена
модель, её калибровка, model card, feature schema и время batch inference.
